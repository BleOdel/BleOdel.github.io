AI Research Assistant

Can an agentic workflow make literature synthesis trustworthy enough to cite — one fetched source at a time?

A structured research framework built on Claude Code that turns literature discovery and synthesis into a repeatable pipeline: search academic databases in parallel, score every source against a fixed rubric, draft a cited report, and have a second agent fact-check every citation before anything compiles.

Stack: TypeScript · Bun · LaTeX/BibTeX · Claude Code skills Sources: arXiv, Semantic Scholar, Google Scholar, OpenAlex

Two tracks, kept deliberately separate

The academic track discovers sources across four connector CLIs, scores them against a fixed evaluation rubric, drafts a cited LaTeX report, and compiles it to PDF. The grey-literature track (/websearch) searches practitioner blogs, engineering writeups and official docs instead, scoring each source on a separate credibility rubric and labelling its independence, then builds a self-contained interactive HTML page.

Academic→ Rubric-scored→ Fact-checked→ Cited PDF

A blog post and a peer-reviewed paper are different kinds of evidence. Merging them into one pipeline would let an unsourced claim sit beside a replicated result with nothing marking the difference — so each track keeps its own state, its own rubric, and its own output format.

The rule everything else follows from

Every claim traces to a source that was actually fetched during the run. A citation that can't be verified against fetched content is treated as a defect, not a stylistic nitpick — the same evidence-first discipline this site's own project pages are held to. A dedicated reviewer agent checks every citation in a drafted report against the source's real content (full text where open access, via a dedicated paper-fetch tool), separately from the agent that wrote the draft.

From discovery to a defensible report

/setup builds a researcher profile from a CV, a reading list, or an interview. /research <topic> searches the connector CLIs in parallel and deduplicates against prior runs. /rank batch-scores a large haul into a shortlist before committing to a full pass. /synthesize <topic> runs the complete drafter-reviewer workflow through to a compiled, verified PDF.

Later commands extend the loop past a single report: /update keeps an existing report current as a living document, /outcome tracks what happened after a synthesis was used, /defend preps a presentation from one, and /gaps reasons across every report on file rather than one at a time. /add-source and /add-template extend the framework itself — a new database connector or a custom LaTeX report format (a thesis chapter, a conference layout) — without touching the core pipeline.

Why it matters

Literature review is exactly the kind of task where an LLM's fluency is a liability if nothing constrains it — a plausible-sounding citation is easy to generate and expensive to catch. Building the fact-checking pass as a separate agent, and the evidence rule as a first-class constraint rather than a prompt suggestion, is the same instinct behind the intrusion-detection and taxonomy work: don't trust a system's output until something independent has checked it against the real evidence.
