Innovate UK KTP · Gener8 Spaces Ltd & Edge Hill University, 2024–Present

Gener8XR: Applied Mixed-Reality Platform Engineering

How do you turn experimental immersive technology into a reusable, maintainable platform?

Through an Innovate UK Knowledge Transfer Partnership, I developed mixed-reality functionality for Gener8XR using Unity and C#, covering UI/UX, spatial interfaces, object interaction, object-state persistence and co-located multiplayer experiences. The demonstrations below show work across the original OpenXR-based implementation and the later Meta SDK pipeline.

My contribution

I designed and implemented spatial interfaces and core MR functionality, including object manipulation, object-state persistence, shared interaction, and HTTP API and WebSocket integration. I also contributed requirements, technical documentation and knowledge transfer.

Persistence and shared interaction

Object-state persistence lets a scene be saved from the wrist panel and restored later: in the walkthrough, a dismantled anatomy model returns to its saved state in one step. Co-located multiplayer lets two headset users in the same room interact with the same virtual objects. Keeping several headsets in agreement about where those objects sit in physical space is the central technical problem in co-located mixed reality.

Bridging Unity and non-technical tools

A bidirectional interoperability layer connects Unity MR scenes to the Intuiface platform through a custom HTTP command API and WebSocket event broadcasting, so live scene content can be controlled through an external interface without opening Unity.

Interaction design and reusable engineering

I designed the core interactive interfaces (radial context menus, wrist-mounted controls, and world-space panels) for spatial usability and clarity in shared MR environments, shaped by what the human-impact study showed about security warnings and cognitive load. A reusable XR development blueprint standardises C# patterns, prefabs and modular architecture, so future projects build on a stable codebase rather than starting from scratch.

Requirements and knowledge transfer

I translated stakeholder discovery and user surveys into a formal Software Requirements Specification (SRS) and Agile user stories, which drove the UX design and development roadmap. I also delivered documentation and internal workshops for non-technical staff on configuring and operating the platform.
