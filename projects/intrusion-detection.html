Telemetry-Driven XR Intrusion Detection

Can runtime telemetry reveal attacks that conventional monitoring may miss?

A telemetry-based intrusion detection system using more than 20 engineered features, PCA dimensionality reduction, and unsupervised anomaly detection across roughly 580,000 time-series windows of VR sensor data.

Model: Isolation Forest (benchmarked against One-Class SVM, LOF, Elliptic Envelope) Result: ≈99% F1, 0–2s detection latency

The pipeline

A telemetry feature pipeline extracts more than 20 real-time signals from the VR session: frame duration statistics, framerate entropy, Head Rotation Interval (HRI) metrics, and quaternion/Euler pose data. Those run across roughly 580,000 time-series windows. Principal Component Analysis reduces this to a compact 5-feature representation optimised for low-latency inference, which an Isolation Forest model classifies as normal or anomalous using a two-second sliding window.

Normal→ Anomalous→ Attack detected

Detection latency by attack intensity

Evaluated against four GPU-based framerate attacks of increasing intensity (larger malicious image payloads loaded into the GPU), requiring a rule of two consecutive anomalous windows before raising a warning. That choice eliminated false positives at the cost of roughly one extra second of delay.

Detection accuracy stayed between 0.97 and 0.99 F1 across all four intensities, with the 1.82MB attack, the fastest to detect, forming the basis of the ≈99% F1 / 0–2s headline figure.

Why unsupervised

Isolation Forest requires no prior assumptions about the distribution of monitored parameters, which matters in a domain like VR security where there's limited existing knowledge of which telemetry signals actually indicate an attack. This let the model learn what "normal" looks like for a given VR system without labelled attack data.
